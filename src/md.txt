# IM Chat · Socket.IO 群聊协议

> 本文档给前端接入群聊实时消息使用。Socket.IO 是事件流，不是普通 HTTP，所以 Swagger 只能展示入口，真正写前端请以本文档和后端代码为准。
>
> 对应后端实现：
> - 入口：`controller/chat/wschat.go` -> `ServeSocketIO`
> - Socket.IO 注册事件：`logic/ws/server.go` -> `NewSocketIOServer`
> - 群聊处理逻辑：`logic/ws/handler.go` -> `HandleGroupMessage` / `GroupMessage`
> - 群聊消息结构：`models.WsGroupMsg`（见 `models/group.go`）
> - 群文件上传：`controller/group/upload.go` -> `UploadGroupFile`

---

## 1. 连接

群聊和私聊共用同一个 Socket.IO 连接。前端登录后，把 JWT token 放在 query 里连接 `/socket.io/`。

| 项目 | 值 |
| --- | --- |
| 协议 | Socket.IO v4，底层 Engine.IO v4 |
| 推荐传输 | `transports: ["websocket"]` |
| 路径 | `/socket.io/`，客户端 SDK 会自动拼接 |
| 鉴权 | query 参数 `token`，值为登录接口返回的 JWT |
| 鉴权失败 | token 缺失、过期、非法时，服务端立即 `disconnect(true)` |
| 重复登录 | 同一个 `user_id` 新连接建立时，旧连接会被服务端踢下线 |
| 离线消息 | 建连成功后，服务端会自动补推未读群聊消息，事件名仍是 `group_message` |

### 浏览器端连接示例

```ts
import { io } from "socket.io-client";

const socket = io("http://<host>:<port>", {
  transports: ["websocket"],
  query: {
    token: localStorage.getItem("token")!,
  },
});

socket.on("connect", () => {
  console.log("socket connected:", socket.id);
});

socket.on("connect_error", (error) => {
  console.error("socket connect error:", error);
});

socket.on("disconnect", (reason) => {
  console.log("socket disconnected:", reason);
});
```

## 2. 群聊事件总览

| 方向 | 事件名 | payload | 用途 |
| --- | --- | --- | --- |
| 客户端 -> 服务端 | `group_msg` | `WsGroupMsg` | 发送群文本消息，或发送群文件消息元数据 |
| 服务端 -> 客户端 | `group_message` | `WsGroupMsg` | 推送群消息、发送 ack、撤回通知、离线未读补推 |
| 客户端 -> 服务端 | `group_recall` | `WsGroupMsg` | 通过 socket 撤回群消息 |
| 客户端 -> 服务端 | `read_group` | `ReadGroup` | 进入群聊时清零该群未读 |

> 群文件有两种方式：
> - 推荐方式：前端先走 HTTP `POST /group/upload/doc` 上传文件。后端落库成功后会自动向群成员推 `group_message`，前端不要再额外 emit `group_msg`，否则可能重复显示。
> - 兼容方式：如果已经有文件 URL，也可以 emit `group_msg`，`msg_type=2`，把 URL 放在 `msg` 或 `url`。

## 3. 消息体 `WsGroupMsg`

`group_msg`、`group_message`、`group_recall` 都使用这个结构。不同事件只用其中一部分字段。

| 字段 | 类型 | 方向 | 是否必填 | 说明 |
| --- | --- | --- | --- | --- |
| `type` | string | C->S / S->C | 是 | 客户端发群消息时传 `group`；服务端推送群消息时是 `group`；ack 是 `ack`；撤回通知是 `recall_group` |
| `msg` | string | C->S / S->C | 文本必填 | 文本内容。文件消息时可以放文件 URL |
| `msg_id` | number | S->C / 撤回 C->S | 撤回必填 | 消息 ID。普通发送时前端不传；服务端推送成功消息和撤回时会带 |
| `url` | string | C->S / S->C | 文件建议必填 | 群文件 URL。`msg_type=2` 时推荐传 |
| `file_name` | string | C->S / S->C | 文件建议必填 | 文件原始名称，用于前端展示 |
| `msg_type` | number | C->S / S->C | 是 | `1` = 文本消息，`2` = 文件消息 |
| `sender_id` | number | S->C | 前端不要传 | 发送者用户 ID。服务端从 token 解析并覆盖 |
| `sender_name` | string | S->C | 否 | 发送者在群里的展示名。优先使用群昵称，空则回落用户昵称 |
| `sender_picture` | string | S->C | 否 | 发送者头像 |
| `group_id` | number | C->S / S->C | 是 | 群 ID |
| `time_string` | string | S->C | 否 | 服务端格式化时间，格式如 `2026-05-28 20:00:00` |

### 后端结构

```go
type WsGroupMsg struct {
    Type          string `json:"type"`
    Msg           string `json:"msg"`
    MsgID         int64  `json:"msg_id,omitempty"`
    URL           string `json:"url,omitempty"`
    FileName      string `json:"file_name,omitempty"`
    MsgType       int    `json:"msg_type"`
    SenderID      int64  `json:"sender_id"`
    SenderName    string `json:"sender_name,omitempty"`
    SenderPicture string `json:"sender_picture,omitempty"`
    GroupID       int64  `json:"group_id"`
    TimeString    string `json:"time_string"`
}
```

## 4. 发送群文本消息

客户端 emit `group_msg`，payload 里传 `type=group`、`group_id`、`msg_type=1`、`msg`。

### JSON 示例

```json
{
  "type": "group",
  "group_id": 10001,
  "msg_type": 1,
  "msg": "大家好，今晚 8 点开会"
}
```

### TypeScript 示例

```ts
socket.emit("group_msg", {
  type: "group",
  group_id: 10001,
  msg_type: 1,
  msg: "大家好，今晚 8 点开会",
});
```

### 服务端规则

- `group_id` 为 `0` 时，服务端丢弃，不回 ack。
- `msg` 为空字符串时，服务端丢弃，不回 ack。
- `sender_id` 不需要前端传，服务端会从 token 解析并覆盖。
- 服务端会把消息写入 Kafka，后续由消费逻辑落库并推送给群成员。
- 如果服务端受理成功，发送方会收到 `group_message`，其中 `type=ack`。

## 5. 发送群文件消息

### 5.1 推荐方式：HTTP 上传

前端先调用普通 HTTP 接口上传文件：

| 方法 | 路径 | Content-Type |
| --- | --- | --- |
| POST | `/group/upload/doc` | `multipart/form-data` |

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 要发送的文件 |
| `group_id` | number | 是 | 群 ID |

请求头：

```http
Authorization: Bearer <JWT>
```

响应示例：

```json
{
  "err": "success",
  "id": 123456789,
  "url": "https://cdn.example.com/f/group.pdf",
  "file_name": "group.pdf",
  "msg_type": 2,
  "time_string": "2026-05-28 20:00:00"
}
```

后端上传成功后会：

- 写入 `group_docs`。
- 更新群会话最后时间。
- 增加其他群成员未读数。
- 写入撤回窗口。
- 自动向群成员推送 `group_message`，`msg_type=2`。

所以这种方式下，前端上传成功后不要再 emit `group_msg`。

### 5.2 兼容方式：已有文件 URL 时 emit `group_msg`

如果前端已经通过别的方式拿到了文件 URL，可以用 socket 发送文件元数据。

```json
{
  "type": "group",
  "group_id": 10001,
  "msg_type": 2,
  "msg": "https://cdn.example.com/f/group.pdf",
  "url": "https://cdn.example.com/f/group.pdf",
  "file_name": "group.pdf"
}
```

```ts
socket.emit("group_msg", {
  type: "group",
  group_id: 10001,
  msg_type: 2,
  msg: fileUrl,
  url: fileUrl,
  file_name: fileName,
});
```

服务端兼容规则：

- `msg_type=2` 时，`msg` 和 `url` 至少有一个非空。
- 只传 `url` 时，服务端会把 `url` 补到 `msg`。
- 只传 `msg` 时，服务端会把 `msg` 补到 `url`。
- 两者都为空时，服务端丢弃，不回 ack。

## 6. 接收群消息 `group_message`

所有群聊相关服务端推送都走同一个事件名：`group_message`。前端需要根据 `type` 区分不同场景。

### 6.1 发送 ack

发送方 emit `group_msg` 后，如果服务端受理，会收到：

```json
{
  "type": "ack",
  "group_id": 10001,
  "msg_type": 1,
  "msg": "ok",
  "time_string": "2026-05-28 20:00:00"
}
```

前端用途：

- 把本地“发送中”的消息改成“已发送”。
- 可以用 `group_id` 找到对应会话。
- 目前 ack 不保证带 `msg_id`，真正的消息 ID 以后端推送的 `type=group` 消息为准。

### 6.2 群文本消息推送

群成员会收到：

```json
{
  "type": "group",
  "msg_id": 123456789,
  "sender_id": 2048,
  "sender_name": "小明",
  "sender_picture": "https://cdn.example.com/u/2048.png",
  "group_id": 10001,
  "msg_type": 1,
  "msg": "大家好，今晚 8 点开会",
  "time_string": "2026-05-28 20:00:00"
}
```

### 6.3 群文件消息推送

群文件消息会收到：

```json
{
  "type": "group",
  "msg_id": 123456790,
  "sender_id": 2048,
  "sender_name": "小明",
  "sender_picture": "https://cdn.example.com/u/2048.png",
  "group_id": 10001,
  "msg_type": 2,
  "msg": "https://cdn.example.com/f/group.pdf",
  "url": "https://cdn.example.com/f/group.pdf",
  "file_name": "group.pdf",
  "time_string": "2026-05-28 20:00:00"
}
```

前端展示建议：

- `msg_type=1`：按文本气泡展示 `msg`。
- `msg_type=2`：按文件气泡展示 `file_name`，点击打开 `url`；如果 `url` 为空，可以 fallback 到 `msg`。
- `sender_name` 和 `sender_picture` 用于群聊消息左侧展示。
- 自己发的消息可以通过 `sender_id === currentUserId` 判断。

### 6.4 离线未读补推

用户重新连接后，服务端会自动查询未读群文本和群文件，并按时间顺序 emit `group_message`。

前端不需要额外请求 socket 离线消息，但通常仍建议：

- 首屏会话列表拉 `GET /chat/show/all`。
- 进入具体群聊页时拉历史记录接口。
- socket 补推用于实时补齐用户离线期间的新消息。

## 7. 前端统一监听写法

```ts
socket.on("group_message", (raw: WsGroupMsg) => {
  switch (raw.type) {
    case "ack":
      markGroupMessageDelivered(raw.group_id, raw);
      break;

    case "group":
      if (raw.msg_type === 1) {
        appendGroupTextMessage(raw);
      } else if (raw.msg_type === 2) {
        appendGroupFileMessage(raw);
      }
      refreshConversationPreview(raw.group_id, raw);
      break;

    case "recall_group":
      markGroupMessageRecalled(raw.group_id, raw.msg_id);
      break;

    default:
      console.warn("unknown group_message type:", raw);
  }
});
```

## 8. 群撤回

群撤回有两套入口：

| 方式 | 入口 | 说明 |
| --- | --- | --- |
| Socket.IO | emit `group_recall` | 适合已经持有 socket 连接的聊天页 |
| HTTP | `POST /group/recall/msg`、`POST /group/recall/doc` | 适合普通接口调用 |

### 8.1 Socket.IO 撤回

客户端 emit `group_recall`：

```json
{
  "msg_id": 123456789,
  "group_id": 10001,
  "msg_type": 1
}
```

```ts
socket.emit("group_recall", {
  msg_id: 123456789,
  group_id: 10001,
  msg_type: 1,
});
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `msg_id` | number | 是 | 要撤回的消息 ID |
| `group_id` | number | 是 | 群 ID |
| `msg_type` | number | 是 | `1` = 文本，`2` = 文件 |

服务端校验：

- 只能撤回自己发送的消息。
- 消息需要仍在撤回窗口内。
- 文本消息查 `group_messages`，文件消息查 `group_docs`。
- 撤回成功后，服务端会向群成员推 `group_message`，`type=recall_group`。

### 8.2 撤回推送

```json
{
  "type": "recall_group",
  "msg_id": 123456789,
  "sender_id": 2048,
  "sender_name": "小明",
  "sender_picture": "https://cdn.example.com/u/2048.png",
  "group_id": 10001,
  "msg_type": 1
}
```

前端收到后：

- 在当前群消息列表中找到 `group_id + msg_id` 对应消息。
- 替换为“消息已撤回”样式。
- 如果撤回的是当前会话最后一条消息，建议刷新会话列表或重新计算 preview。

### 8.3 HTTP 撤回

文本消息：

```http
POST /group/recall/msg
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{
  "msg_id": 123456789,
  "group_id": 10001
}
```

文件消息：

```http
POST /group/recall/doc
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{
  "msg_id": 123456790,
  "group_id": 10001
}
```

## 9. 群已读

进入群聊页面时，前端应该把该群未读清零。

### 9.1 Socket.IO 已读

```json
{
  "group_id": 10001
}
```

```ts
socket.emit("read_group", {
  group_id: 10001,
});
```

规则：

- `user_id` 由 token 解析，前端不用传。
- 后端会把当前用户在该群的未读数清零。
- 后端会把 `group_read_position.last_read_msg_id` 推进到该群最新一条 `group_messages.id`。
- 5 秒幂等锁：短时间重复发送会被直接视为成功，不会重复清零。
- 服务端不会额外推送已读成功事件。

### 9.2 HTTP 已读

```http
POST /group/read
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{
  "group_id": 10001
}
```

## 10. 配套 HTTP 接口

这些接口不是 Socket.IO，但群聊页面通常会用到。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/chat/show/all` | 主页混合会话列表，包含私聊和群聊、未读数、最后消息时间 |
| GET | `/group/create/list` | 当前用户所在的群列表，不含未读数，常用于转发选群 |
| POST | `/group/one/main` | 查询某个群在当前用户视角下的群信息 |
| POST | `/group/show/all` | 查看群成员列表 |
| POST | `/group/upload/doc` | 上传群文件并自动推送群文件消息 |
| POST | `/group/read` | 群已读 |
| POST | `/group/recall/msg` | 撤回群文本消息 |
| POST | `/group/recall/doc` | 撤回群文件消息 |
| POST | `/group/change/user/rename` | 修改当前用户在该群里的群昵称 |
| POST | `/group/change/re/name` | 修改当前用户侧边栏看到的群名 |

## 11. TypeScript 类型建议

```ts
export type GroupMessageType = 1 | 2;

export type GroupSocketMessageKind =
  | "group"
  | "ack"
  | "recall_group";

export interface WsGroupMsg {
  type: GroupSocketMessageKind;
  msg?: string;
  msg_id?: number;
  url?: string;
  file_name?: string;
  msg_type: GroupMessageType;
  sender_id?: number;
  sender_name?: string;
  sender_picture?: string;
  group_id: number;
  time_string?: string;
}

export interface SendGroupTextPayload {
  type: "group";
  group_id: number;
  msg_type: 1;
  msg: string;
}

export interface SendGroupFilePayload {
  type: "group";
  group_id: number;
  msg_type: 2;
  msg?: string;
  url?: string;
  file_name?: string;
}

export interface RecallGroupPayload {
  msg_id: number;
  group_id: number;
  msg_type: GroupMessageType;
}

export interface ReadGroupPayload {
  group_id: number;
}
```

## 12. 前端封装示例

```ts
export function sendGroupText(socket: Socket, groupId: number, text: string) {
  const msg = text.trim();
  if (!msg) return;

  socket.emit("group_msg", {
    type: "group",
    group_id: groupId,
    msg_type: 1,
    msg,
  } satisfies SendGroupTextPayload);
}

export function sendGroupFileByUrl(
  socket: Socket,
  groupId: number,
  fileUrl: string,
  fileName: string,
) {
  if (!fileUrl) return;

  socket.emit("group_msg", {
    type: "group",
    group_id: groupId,
    msg_type: 2,
    msg: fileUrl,
    url: fileUrl,
    file_name: fileName,
  } satisfies SendGroupFilePayload);
}

export function recallGroupMessage(
  socket: Socket,
  groupId: number,
  messageId: number,
  msgType: GroupMessageType,
) {
  socket.emit("group_recall", {
    group_id: groupId,
    msg_id: messageId,
    msg_type: msgType,
  } satisfies RecallGroupPayload);
}

export function markGroupRead(socket: Socket, groupId: number) {
  socket.emit("read_group", {
    group_id: groupId,
  } satisfies ReadGroupPayload);
}
```

## 13. 推荐页面接入流程

1. 用户登录后拿到 JWT。
2. 建立 Socket.IO 连接，query 里带 token。
3. 注册 `group_message` 监听。
4. 拉 `GET /chat/show/all` 渲染会话列表。
5. 进入某个群聊页面时，拉历史记录或群信息接口，然后 emit `read_group` 清未读。
6. 发送文本时 emit `group_msg`。
7. 发送文件时优先调用 `POST /group/upload/doc`，等待后端自动推送 `group_message`。
8. 收到 `group_message(type=group)` 时追加消息。
9. 收到 `group_message(type=ack)` 时更新发送状态。
10. 收到 `group_message(type=recall_group)` 时把对应消息改为撤回状态。

## 14. 常见坑

- 不要给群消息传 `receiver_id`，群聊使用 `group_id`。
- 群文件字段叫 `url`，私聊文件字段叫 `file_url`。
- 群聊服务端推送事件名是 `group_message`，私聊是 `message`。
- 群聊发送事件名是 `group_msg`，私聊是 `msg`。
- `sender_id`、`sender_name`、`sender_picture` 都以后端推送为准。
- HTTP 上传群文件成功后，后端已经推送群文件消息，前端不要重复 emit。
- ack 只是“服务端受理”，不是完整消息体；真正用于渲染的消息以 `type=group` 为准。
- 进入群聊页后记得 emit `read_group` 或调用 `/group/read`，否则会话列表未读数不会清零。
